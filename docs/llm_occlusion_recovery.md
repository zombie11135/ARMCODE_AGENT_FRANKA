# LLM 单步遮挡恢复试验（2026-10-22）

已在原 agent 的几何清障子任务中接入可选的 LLM 恢复规划器。模型从当前允许的动作中选择下一步；执行器取得新观测后重新构建动作菜单。它不输出任意代码或运动坐标，不重置清障次数，不修改感知门槛。

**最新策略（2026-10-23）：当前腕部关系图驱动的清障与目标检查不设置深度覆盖率下限，掩码触边和重叠注记也只作诊断。节点只因空掩码、没有有效测量点等缺少抓取输入的问题被质量检查拦截；可见表面能否抓取由后续 AnyGrasp 判断。以下历史回放中提到的 80% 是当时的策略，不代表当前限制。**

本轮只进行了真实模型的历史日志回放，以及使用模拟相机、机械臂、夹爪的回归测试。没有打开相机、连接机器人或执行真机动作。尚未证明真实场景中的整体任务成功率或探索步数提升。

## 运行中的恢复循环

```text
当前 RGB-D / 目标身份 / 几何判断
  → 构建事实快照和允许动作菜单
  → LLM 选择一个动作并给出依据
  → 校验快照 ID、动作参数、图文件、源文件、场景有效性
  → 同位重采集 / 前往已配置观测位 / 选择合格清障节点 / 暂停
  → 新观测重新判断；目标已确认且几何满足条件时继续原抓放任务
```

模型可以提出的动作：

- `observe:current`：强制新采集，绕过原照片缓存，不发出移动。每次清障/换视角之间最多做一次原位补拍；即使仍有总观察预算，也不会连续选择同位重拍。
- `observe:view_1` 等：只对应本轮通过 CLI 明确配置的观测法兰位姿；仍通过原 MoveIt 运动接口执行。在 dry-run 中不提供需要实际移动的观测菜单，避免把未移动的相机当成新视角。
- `clear:<当前节点 ID>`：只在几何规则允许、还有清障预算和未占用缓冲槽位时出现，仍使用原清障技能、掩码与抓取规划。
- `pause`：条件不足时保存依据并退出当前执行，报告 `recovery_pending=true`，不视为已完成目标。

明确保留的约束：

- 目标名称不变，未知节点不由模型强行命名，观察成功不等于目标识别成功。
- 深度覆盖率、掩码触边和重叠注记只用于诊断，不否决目标或遮挡物。快照 `quality_issues` 只列缺少有效掩码/测量点的问题，`quality_diagnostics` 保留原注记；图中关系和目标身份关联照常判断，具体能否抓取交给后续抓取规划。
- 模型返回后会再次校验动作菜单；错误格式、陈旧快照、虚构节点、任意位姿、修改门槛等输出不能执行。
- 抓取前仍检查图文件哈希、RGB-D 文件绑定、场景 epoch、观测位姿和有效期。
- 一个清障槽位在执行前即被预留，失败或部分运动也不会把它重新标成空闲。
- 已占用缓冲区附近的候选按保存的采集几何投影到基座系后排除；无法完成此投影时，不允许继续清障以免误用缓冲区。当前排除使用可见表面中心与缓冲点 XY 的 12 cm 邻域，是保守空间排除，不是完整物体跟踪。
- 未能确认停止、控制器/夹爪/通信故障仍会终止运动恢复，不交给 LLM 改写为成功。

LLM 请求最多等待 30 秒；无可用响应或校验失败时不执行其建议。一次成功的限流闭合仍只表示闭合命令完成，不表示视觉上确认了物体已经搬走。

## 原 agent 启用方式

保持现有完整交互 agent 启动命令，在几何遮挡模式下追加：

```bash
--enable_llm_occlusion_recovery \
--geometry_occlusion_observation_budget 2
```

按你指定的缓冲释放位——基座系法兰 `(450, -400, 300)` mm——启动示例：

```bash
export FR3_AGENT_PYTHON="$PWD/.venv-mobileclip2-fr3/bin/python"
bash run_fr3_agent.sh \
  --use_llm_planner \
  --enable_geometry_occlusion \
  --disable_geometry_occlusion_auxiliary \
  --enable_occlusion_recovery \
  --occlusion_allow_unlocalized_target \
  --occlusion_recovery_max_attempts 1 \
  --geometry_occlusion_buffer_xyz_mm 450 -400 300 \
  --enable_llm_occlusion_recovery \
  --geometry_occlusion_observation_budget 2 \
  --arm-speed 0.10 \
  --execute_robot
```

此示例命令允许真实运动，本轮开发中未运行。没有确认可用的备用观测位，因此没有替用户填入新观测坐标；仅上述参数时模型只能选择同位重采集、合格清障或暂停。

提供备用观测位时，重复使用 `--geometry_occlusion_recovery_view_pose_mmrad`，每组为基座系法兰 X Y Z RX RY RZ（毫米、弧度）。按输入顺序对应 `view_1`、`view_2`。不要使用回放中的模拟视角名代替实际配置。

## 状态记录与当前边界

恢复在同一个 `SimpleRobotActions` 对象中执行，不通过重新建立整个 executor 实现，因此本轮清障次数、已用槽位与额外观测次数不会在模型调用之间重置。全局 `automatic_replan=false` 对几何中断仍保留，避免旧的整任务重跑通道重置状态。

额外观测预算按目标分别计算，清障预算与其独立。模型不得增加任一预算。例：唯一缓冲位已占用时，即使新深度变好，也不能再搬第二个物体到同一槽位；需要另外配置空闲缓冲位并给出相应清障预算。

运行记录：

- `runs/current_capture/occlusion_recovery_llm/`：事实快照、模型原文、允许菜单与校验结果。
- `runs/current_plan/occlusion_recovery_state.json`：本轮已预留/完成的清障记录、槽位占用、观测次数。
- 原执行记忆的 `geometry_recovery` 字段：同一任务的恢复审计副本。

这些记录用于本轮审计，**不自动恢复到重启后的新任务**。本版没有实现跨进程的暂停续跑，也没有实现一般的跨帧实例跟踪、完整搬运效果视觉验证或目标候选位置的概率更新。历史中显式记录 `visual_effect_verified=false`，模型不能据一次技能完成就排除整堆。

## 历史 22:23 实验：为什么没有调用清障（当时仍有 80% 限制）

这次真实运行的 `clear_count=0`、`clear_limit=1`、缓冲位空闲。第一帧是 `no_search_evidence`：尚未形成遮挡边；原位补拍后出现 N2→N3，但 N2 的有效深度覆盖为 69.9%，下一次补拍为 69.5%，低于现有 80% 要求，所以都是 `blocker_quality_insufficient`。模型三次可选菜单中均没有 `clear`；清障技能仍在原调用链中，根因是动作资格筛选。

本轮调整：

- 模型提示明确区分“目标未知”和“禁止清障”；有通过资格检查的 `clear` 时优先推进原清障技能。
- 修正提示中“观察预算耗尽就暂停”的过度约束：观察预算不限制仍合法的清障动作。
- 一次额外原位补拍后，不连续原位重拍；仍可选择合法清障或明确配置的不同观测位。两种预算独立，未消费的观察预算不代表一定还有可用视角。
- 日志与快照显示几何状态、合法清障候选数、剩余次数、空闲缓冲位和拦截原因。深度不足时同时输出实际比例与要求，暂停报告明确“清障尚未执行”。
- 保留当前深度要求，不将低质量候选或无关系节点变成可执行清障对象。这次现场的原始深度仍不满足清障要求，调度修改不能替代深度质量改善。

真实 `qwen-vl-8b` 离线回放：实际首帧选择 `observe:current`；实际一次补拍后的证据选择 `pause`，明确深度不足且无 `clear`；另外一组完全模拟的合格候选，在观察预算为 0 时选择 `clear:synthetic_blocker`。最后一组不是本次现场深度，所有回放均未执行动作。证据目录：`runs/occlusion_recovery_policy_replay/20261022-6cbe8bd5/`。

回归另修复了几项纯逻辑测试引用 `runs/current_capture/wrist_depth.png` 的环境依赖：替换为明确不可用的测试深度路径，不再读取真机现场文件。真实深度判别测试继续使用各自的临时数据，现场记录未修改。

本次核心回归 `461 passed, 2 skipped`，另有 8 项可学习门控测试通过；新增覆盖合法清障不受观察预算影响、阻止连续同位补拍、清障/换视角后允许一次新补拍，以及深度拦截原因输出。

## 当前更新：移除深度覆盖率限制

用户明确要求去掉这一限制后，移除整个关系图清障链路中的比例拦截：

- 新关系图不再把覆盖率低于 80% 标为阻断问题；保留掩码像素数、有效深度像素数与覆盖率。
- 清障候选筛选、目标就绪检查和清障技能入口不再检查覆盖率下限；旧报告中的 `low_depth_coverage` 也不再阻断，原文件与哈希不改写。
- 当前图驱动清障不再受旧 bbox 路径的 ROI 深度有效比例门槛影响。旧 bbox/VLM 清障路径的独立 ROI 逻辑保持原状。
- 恢复快照明确 `depth_coverage_filter_enabled=false`、`min_depth_coverage=null`；模型提示与日志不再用 80% 或其他覆盖率比例拒绝合法清障候选。
- 仍要求至少存在真实有效测量点；掩码、观测来源、场景版本、关系图、缓冲位和原抓取/碰撞规划检查保持有效。不会填补或伪造缺失深度。

沿用原启动命令，重启 agent 后生效，无需新增参数。旧的 `min_depth_fraction` 调用参数仅为接口兼容保留，不再生效。

验证：核心回归 `466 passed, 2 skipped`；模拟 70% 深度覆盖、并把旧 ROI 参数设为 99% 的情况下，启用/关闭 LLM 恢复均能完成清障→重观察→抓取→放置。使用最新真实 N2 记录（7,795/10,916，71.4%）调用当前 `qwen-vl-8b`，模型选择该节点的 `clear`，同帧证据/掩码入口检查通过；未执行真实清障、抓取规划或任何运动。记录：`runs/depth_coverage_gate_removed_replay/20261022-d3f28855/`。
