调度方式
  大模型仍负责上层任务步骤，如 observe/grasp/place；图片匹配等基础操作由技能内部程序调度。
  登记物体：一次 GroundingDINO 类别检测 -> MobileCLIP 批量编码候选 -> 与图库匹配。
  请求身份排名第一、余弦相似度 >= 0.86、超过其他登记身份 >= 0.05，才接受图片证据。
  匹配明确：若需要 mask，仅给选中的一个目标做 SAM3，随后沿原接口调用 AnyGrasp。
  匹配不明确、未登记或模型出错：回退原多提示词检测/SAM/OCR/验证流程。
  显式 strict OCR 模式保持原语义，直接走原流程。
  原有 VLM 仍可用于任务描述/验证；本次没有新增逐候选大模型调用。
  新增独立技能 register_object_reference / match_object_reference / recognize_object，旧技能未删除。
  图片身份是独立 evidence，未伪装成 OCR 文本、OCR 分数或 VLM 置信度。
  gate 仍检查可见性、深度和遮挡；匹配通过不代表已确认可抓或已完成轨迹规划。

节省时间的具体措施
  图库特征持久化缓存；图片、模型或编码配置变化时重建，修改名称/别名/品牌不重算向量。
  候选区域批量编码；同一 Agent 进程复用模型。OCR 到需要时才加载。
  检测和候选特征按图片内容 SHA256、参数缓存；即使文件名相同，内容变化也重新计算。
  同一张图可为多个登记名称复用检测和特征；不缓存并复用机器人运动轨迹。
  分割只针对选中的实例；不对所有可用技能逐个调用，也不新增多轮 LLM 调度。
  首次模型加载、原 OCR 回退、任务 VLM、AnyGrasp 和 MoveIt 仍有各自延迟。
  Open3D 预览等待人工关闭的时间也不属于视觉推理速度；此次没有改变预览设置。

登记新物体（以下命令只读取图片、写图库，不连接硬件）
  cd "/home/seur/data/wpy/armcode-agent (1)/armcode-agent"

  # 查看现有名称和数量
  /home/seur/data/wpy/conda_envs/env_armcode_agent/bin/python -m hardware.reference_cli list

  # 把实际图片路径填在 --images 后；推荐先准备 5-10 张不同角度、距离的独立目标裁图。
  # 以下路径仅为示例。不要把整张杂乱桌面直接作为目标参考图。
  /home/seur/data/wpy/conda_envs/env_armcode_agent/bin/python -m hardware.reference_cli register \
    '抗病毒颗粒' --category medicine_box --prompt 'medicine package' \
    --images /path/to/front.png /path/to/side.png /path/to/oblique.png

  # 方块示例（可指定别名；别名要指同一个身份，不要合并不同药品/规格）
  /home/seur/data/wpy/conda_envs/env_armcode_agent/bin/python -m hardware.reference_cli register \
    '红色方块' --category cube --prompt 'cube' --alias 'red cube' \
    --images /path/to/red_cube_front.png /path/to/red_cube_side.png

  整张场景图也可登记：每次传一张图并追加 --bbox x1 y1 x2 y2，单位像素，裁框后入库。
  同名追加时 category/prompt 必须与该物体已登记设置一致；重复图片不重复计数。
  图库不自动吸收模型预测，避免一次误认污染后续识别。
  正反面、包装相似的不同药品应分别登记；补充本机腕部 D435i 的当前光照与视角。
  模型分数不是校准概率；不要仅为了提高命中数直接调低阈值。
