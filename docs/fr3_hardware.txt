2. 配置入口

config/hardware/fr3.yaml 是新硬件配置的唯一主入口：
  arm.workspace                  原 Docker 工作区的绝对路径
  arm.stack                      real 或 fake；CLI --stack 可覆盖
  arm.speed_scaling              默认 0.10，MoveIt 速度/加速度缩放
  arm.position_tolerance_m       默认 0.003 m
  arm.orientation_tolerance_rad  默认 1 度，文件用弧度填写
  arm.request_timeout_s          含规划与运动；超时会停止本次请求并清理控制器
  arm.home_pose                  待配置，不使用旧 xArm home
  gripper.port                   固定为剩余 RS-485 设备 DAAL8LK6 的 by-id 路径
  gripper.speed_raw / force_raw  0..255 协议值，不是 mm/s 或牛顿
  gripper.keepalive_interval_s   会话内只读保活周期，默认 0.1 s
  gripper.startup_timeout_s      首次连接用只读轮询等待 0x09 清除的最长时间，默认 1 s
  gripper.state_timeout_s        状态更新/缓存过期阈值，默认 0.5 s
  cameras                        两台相机的序列号和已测试的 640x480 / 6 FPS 配置
  perception                     模型路径占位；本阶段不切换抓取算法
  calibration_file              已指向 ../calibration/fr3_handeye.yaml，相对硬件 YAML 所在目录解析

相机 global / wrist 的分配按此前画面暂定，标定前需要确认实际安装角色。
旧 --xarm_ip、--handeye_config、ROS 1 夹爪与旧设备序列号等参数仅用于 --legacy-xarm。
新 FR3 模式以上述 YAML 为准；LLM/API 等非硬件参数仍沿用现有入口与环境变量。
没有把 API 密钥写进配置文件。

工作台、夹爪碰撞模型继续由原工作区 config/workcell.json 管理，避免维护两套值：
  桌面：fr3_link0 的整个 z=0 平面，另加 0.01 m 净空。
  工具：直装、法兰到最远端 0.17 m（2026-10-14 用户重新测量）、最大外宽 0.10 m，另加 0.005 m 包围体余量。

6. Robotiq 2F-85 独立接口

  python -m hardware.cli gripper ports

这个命令只列出系统端口，不打开串口。
用户移除多余夹爪后，系统只剩下以下 USB/RS-485 设备，已写入 YAML：
  /dev/serial/by-id/usb-FTDI_USB_TO_RS-485_DAAL8LK6-if00-port0

已在 115200、8N1、Modbus slave 9 下确认状态寄存器可读。
如果设备改过地址或波特率，也需填实际值。

  python -m hardware.cli gripper status
  python -m hardware.cli gripper check --duration 120 --interval 0.1

check 仅持续读取状态寄存器，不接受 --execute，也不会激活、开合或复位。
其传输层只允许 FC03 读取 0x07D0 开始的三个寄存器，其它请求会直接拒绝。
每 10 秒打印进度，结束后返回 JSON；逐次采样 JSONL 和统计 JSON 保存到
runs/hardware_validation/robotiq-comm-<时间戳>.*，可用 --output-dir 指定目录。
统计包含成功/失败次数、响应时间、最大读取间隔、故障码和位置编码范围。
首次两秒内的 0x09 单独记录，稳定阶段再出现故障或任何读取错误都会使检查不通过。
communication_passed 表示通信检查通过；all_steady_samples_ready 单独表示夹爪是否就绪，
未激活但正常响应的夹爪也可以通过通信检查。读取异常不自动重连、清错或重试。
命令结束就关闭串口；它不是 Agent 的后台保活服务，也不证明机械开合或夹持力正常。

推荐使用常驻终端测试；启动只建立只读通信，不自动激活或开合：

  python -m hardware.cli gripper console --execute --speed-raw 32 --force-raw 32

进入 robotiq> 提示符后，由操作者逐条输入（先空载测试）：
  status
  open
  close
  move 128
  open
  quit

如果 status 显示未激活，需你显式输入 activate，然后重新查看 status。
已激活且正常的夹爪不会因 activate 命令而重复标定。
console 不加 --execute 则为只读终端，即使输入 open/close 也会被拒绝。
命令等待输入期间、每个动作期间及两个动作之间均持续只读保活。
不要同时打开两个夹爪终端或运行其它串口客户端，端口为独占访问。
stop 停止夹爪；Ctrl-C 在动作等待期间会尝试停止该动作并返回提示符，
在等待输入时按 Ctrl-C 则退出会话。quit/退出不自动张开，退出后不再保活。

open 32 32、close 32 32、move 128 32 32 可以覆盖本次动作的速度和力度。
所有数值均为 0..255 协议编码，不是毫米、mm/s 或牛顿；128 不是经过标定的精确半开宽度。
每个动作会等到位置到达或接触停止后返回状态；empty close 可完成动作但不会标为检测到物体。
后台通信异常会保持故障记录并阻止新动作，不因后来的好数据而悄悄清除。
排查后可显式输入 reconnect，只重开通信并重新读取，不复位夹爪、不重试之前的动作。
session.error、monitor_alive、last_status_age_s 和 write_register_requests 可以用于诊断。
终端命令和结果会保存到 runs/gripper/session-<时间戳>.jsonl。

也支持以下一次性命令，由操作者单独执行；它们完成后会结束当前串口会话：
  python -m hardware.cli gripper activate --execute
  python -m hardware.cli gripper open --execute
  python -m hardware.cli gripper close --execute
  python -m hardware.cli gripper move 128 --execute
  python -m hardware.cli gripper stop --execute

status 读取原始状态寄存器，不启动后台保活。activate 在未激活时会执行自身标定运动，必须由操作者显式执行。
open/close 不会隐式激活。动作建立会话时，首读 0x09 只通过后续只读查询等待恢复；不写复位寄存器。
其它故障、启动 0x09 持续超时、已建立会话后再次出现 0x09 都会阻止新动作，不自动恢复或重试。
运动超时/中断会尝试清除 rGTO 停止本次运动，不自动张开。

返回 activated、activation_state、go_to、fault、position_raw、requested_position_raw、
current_ma、object_state_label、object_detected_closing 等字段。
0..255 是位置编码值；不把它当成精确夹距，也不把电流当成测得的夹持力。
object_detected_closing 仅表示闭合时检测到接触，不是抓取成功的视觉证明。
Agent 按用户要求在正常闭合完成后继续，允许“闭合到底且没有检测到接触”；接触状态仍按实际记录。
端口独占打开、CRC/应答地址/功能码/写入确认均校验。

7. Python 接口

  from hardware.config import load_config
  from hardware.fr3 import FrankaMoveItArm
  from hardware.interfaces import Pose6D
  from hardware.robotiq import Robotiq2F85

  cfg = load_config()
  arm = FrankaMoveItArm(cfg.arm, stack='fake')
  current = arm.get_pose()
  target = Pose6D(current.x + 0.005, current.y, current.z,
                  current.rx, current.ry, current.rz)
  plan = arm.plan_pose(target)

调用 move_pose 必须构造 execution_enabled=True 的适配器。
Robotiq2F85 同样默认禁止动作；状态读取可以不启用 execution_enabled。
使用 with Robotiq2F85(cfg.gripper) as gripper 可在结束后关闭串口。
夹爪 close() 表示闭合，disconnect() 才是关闭串口。

常驻 Python 用法（动作行由操作者执行）：

  with Robotiq2F85(cfg.gripper, execution_enabled=True) as gripper:
      state = gripper.start_session()  # 仅通信握手和只读保活，不自动激活
      print(state.to_dict())
      # gripper.activate()             # 只有确认需要激活时显式调用
      gripper.open(speed_raw=32, force_raw=32)
      gripper.move_raw(128, speed_raw=32, force_raw=32)
      result = gripper.close(speed_raw=32, force_raw=32)
      print(result.to_dict())
      gripper.assert_healthy(require_ready=True)
      # 此处执行其它任务时，后台状态读取仍然运行。

start_session() 也能在 execution_enabled=False 时使用，动作接口仍被禁止。
各动作本身会在首次调用时建立会话。后台读写和前台命令共用锁，防止 Modbus 数据交错。
disconnect() 先结束轮询线程再关闭串口，不发送释放或开合指令。

core.RuntimeContext 新增 arm / gripper / transforms 三个字段。
hardware.runtime.build_hardware(...).attach(context) 可注入新接口。
attach(context, monitor_gripper=True) 会建立夹爪会话并检查就绪；FR3 运行时已接入此模式，
disable_grip 时不连接夹爪。完整任务仍受未完成的标定/坐标迁移检查限制。
旧技能使用的机械臂适配器会在移动前后检查夹爪会话健康；通信异常阻止后续步骤。
本轮没有实现夹爪故障触发正在执行的 FR3 轨迹自动取消，不把这项前后检查当作联动急停。
LegacyPoseAdapter 只兼容旧技能的 get_position / set_position，转换毫米到米；
不伪装完整 xArm SDK。旧速度参数会提示忽略，实际用 YAML 的 MoveIt 缩放。
输入必须已经是 FR3 基座系法兰位姿；单位转换不等于坐标变换。

11. 18 cm TCP 初值与开合轴对照

用户说明法兰到实际抓取中心约 18 cm、没有横向偏移，且为直装。
当前 T_flange_tcp 平移为 [0, 0, 0.18] m，旋转为单位矩阵。
这里的单位旋转是软件对 TCP 坐标轴的定义：三根轴保持与 fr3_link8 平行，只平移原点。
它不表示真实夹爪开合方向已经与法兰 X 或 Y 轴对齐。
原 workcell.json 中 0.19 m 工具碰撞包围体保持原值；TCP 长度不改变最远端碰撞体积。

此前用户不确定法兰系开合方向时，准备了如下对照命令。在 env_armcode_agent 中执行：
  python -m hardware.cli calibration axes --current-pose
该命令仅请求已有适配器的 get_pose；要求 ROS 真机栈已运行且状态可读，不会自动启动栈，
不激活控制器、不规划、不发送运动或夹爪指令、不修改 TCP 或对齐配置。
输出 flange_axes_in_base 是法兰 X/Y/Z 在基座坐标系中的方向，
candidates 给出“开合沿法兰 X”和“开合沿法兰 Y”两种假设对应的基座方向。
对照两指之间的连线，不要把手指伸出去的长度方向当作开合方向。
两候选仅供比较；实际安装也可能相对 X/Y 为斜角。相反方向描述同一条开合直线，
但可能对应相差 180° 的法兰姿态，需要后续规划检查与择优，不自动猜一个方向执行。

如果已知当前法兰位姿，可完全离线计算。例如以下仅为演示输入，不会移动到该姿态：
  python -m hardware.cli calibration axes --flange-pose 0.35 0 0.5 3.141592653589793 0 -1.5707963267948966
这个示例下，法兰 +X 约指向基座 -Y，法兰 +Y 约指向基座 -X，工具向基座 -Z 伸出。
--closing-axis-flange DX DY DZ 可输入观察到的方向，输出对应旋转候选，但仍不写入配置。

GSNet 的 Gx 为接近方向，Gy 为两指连线，Gz=Gx×Gy。
直装时，接近方向 a_F=[0,0,1]，若实际开合方向为 b_F，则：
  R_flange_grasp = [a_F, b_F, a_F×b_F]
  R_grasp_tcp = transpose(R_flange_grasp)  （因本项目定义 R_flange_tcp=I）
长度补偿通过 T_base_tcp @ inverse(T_flange_tcp) 应用，随法兰姿态一起旋转，
不会固定从基座 z 坐标减去 0.18 m，也不会在模型对齐矩阵中再次扣除这段长度。

旧 skill_lib/manipulation/plan_grasp_with_anygrasp.py 保留原 xArm 的额外 -90° 与 0.12 m
补偿；这些属于显式 legacy 入口，不能直接搬到新 FR3 链路。新对齐工具不调用该旧变换。
模型的 depth 参数与最终选用的抓取参考点将在 GSNet 服务接入时单独处理，不混入安装角度。

输出 observed_base_line 内含相对法兰 X/Y 的夹角，以及与法兰 XY 平面的偏离角。
目视“沿 Y”可能只是近似描述；工具会明确报告投影误差，不自动把它当作精确标定。
