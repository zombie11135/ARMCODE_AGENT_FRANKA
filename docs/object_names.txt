名称分三类
  name / aliases：同一物品的明确名称，跨物品不能重复。
  attributes.brand / descriptors：品牌或共享描述，允许多个物品使用，需要图像消歧。
  task binding：用户给下一次任务的临时指代，不写入永久图库。
  名称先做 Unicode NFKC、大小写及连续空白归一化；不自动丢弃剂型、规格或数字。
  未登记名称继续走原流程。不同产品/剂型/规格应使用不同身份，不能仅因包装像就合并。

场景消歧
  用户只说品牌（例如 999）时，名称解析先返回相关身份集合。
  Planner 目录包含编号、别名、品牌等，现有 LLM 调用可使用这些信息解释叫法；
  不增加一个逐物品 LLM 循环，不自动把模型猜测写成永久别名。
  规划之后还会做确定性检查，已知共享名称不能仅由 LLM 猜成某一个候选。
  执行器在建立运动/夹爪会话和回 home 之前，读取一张新的腕部图像进行身份匹配。
  此分支只做检测和图片匹配，不做 SAM、抓取规划或运动；相同检测提示词共用检测缓存。
  一个身份达到图片匹配阈值：绑定该编号；多个或零个确认身份：返回需要澄清的失败报告。
  名称歧义不自动重规划重试；交互循环保留，可以换完整名称重新输入任务。
  视觉唯一性是“当前腕部视角中被可靠匹配的唯一登记身份”，不保证视野外没有同品牌物品。
  视野不完整或物品外观相似时，可直接用完整名称/编号，或明确做临时绑定。
  一般未登记的自由语言理解仍由原规划与 OCR 流程承担，不是任意称呼都能被自动理解。

只测试名称解析
  "$ARM_AGENT_PY" -m hardware.reference_cli resolve '抗病毒口服液'
  "$ARM_AGENT_PY" -m hardware.reference_cli resolve '999'

  unknown：没有登记该叫法，不能仅靠名称表确定。
  以上命令不会加载视觉模型，也不连接硬件。
  名称表不自动猜测“999”属于哪个产品；填写品牌后 resolve 才会返回相应候选。

Agent 中的临时指代
  原启动命令继续使用，先退出并重启 Agent 加载本次代码。
  在 armcode> 提示符中输入：
    /names
    /bind 999 = 抗病毒口服液
    把999放到粉色盘子里

  /bind 的右侧也可以写 /names 列出的 ref_ 编号。
  绑定仅给紧接着的下一次任务；开始任务时消费，即使任务失败，也不会沿用到下一次任务。
  同一次任务内的重规划仍使用该绑定；新任务需要重新绑定或使用明确名称。
  /bind-clear 可在开始任务前取消所有临时绑定。
  /names 会显示下一次任务的绑定。不能用临时别名覆盖另一物品已有的正式名称/编号。
  这些三个名称命令本身不拍摄、不控制硬件；普通任务仍按原启动模式执行。
