计时边界（全部秒，使用单调时钟）

CAPTURE：校准腕相机获取新 RGB-D 帧，包括等新帧、图像/点云准备和落盘。
  相机持续流式采集，不能把它称为单次传感器曝光时间。缓存命中不伪装成采集。
  获取拍摄前后 FK、相机启动预热、最终冻结文件另在原始跨度中，不属于 CAPTURE。
PERCEIVE：目标身份识别、SAM/遮挡关系、容器识别及坐标计算。同类重叠跨度取并集。
GRASP_PLAN：抓取候选服务，包括 GPU 锁等待、模型进程初始化、推理与候选筛选/IO。
  明确记录实际 backend 和 inference_cache_hit。不是只测一次 CUDA 前向推理。
  后续机械臂 IK 和 MoveIt 轨迹计算不算进这个阶段。
MOTION_PLAN：现有 /plan_kinematic_path 规划服务调用墙钟，包含服务可用性等待及通信。
  同时保留 response.motion_plan_response.planning_time 为 server_planning_s；
  该字段是服务端自报规划时间，与主机测得服务耗时分别使用。
  FR3规划准备总计另记：涵盖硬件/场景状态检查、IK、候选检查、MoveIt、路径审查。
  不要将 prepare 总计或“机械臂调用(move)”误当纯规划时间。
MOVE：现有 FollowJointTrajectory 目标被接受后，等待终态结果的墙钟。
  包括控制器实际执行和结果通知延迟；不含控制器激活、目标握手、末端验收与清理。
  这是控制器执行接口的测量边界，不是按关节速度阈值测得的严格运动起止。
  未发送/未接受目标不会产生 MOVE；超时/中断记录已等待区间并标为 error，
  原有取消/停控/清理照常运行，清理耗时仍在 RPC/TOTAL 中。
GRIPPER：原夹爪开/合回调及完成反馈等待；不把启动会话当开合。
VERIFY：真正调用抓取/放置验证技能的时间。跳过验证不会填一个假的成功验证。
  原控制策略可能接受低置信度“未确认”；现在不更改它。
  验证技能失败与整体任务返回成功可同时出现，需检查 failed_calls 和原始证据。
  不把 FR3 末端到位验收当作物品已进盘的验证。
HANDOFF：上一个成功控制器执行区间结束，到下一个控制器执行区间开始。
  采用上述 MOVE 接口边界，是运动衔接间隔估计；包含期间规划、感知、夹爪等，
  与那些阶段重叠。不是只表示 CPU 空闲，不含首段运动前/末段运动后时间。
  使用同一 boot ID + time namespace 的时钟。无法对齐、前段失败、
  中间运动请求丢失遥测时不编造间隔。
TOTAL：现有任务入口到返回/异常的墙钟。保留加载、清理、恢复、人工预览等待。
  不含交互输入任务前的等待，也不含入口之前启动 VLM 的时间。

原始 spans 和 summary 保留；新增 phases、recovery_events、phase_schema。
每阶段 wall_s 是本阶段跨度并集；work_s 是调用耗时之和。
不同阶段仍可重叠，不得累加来替代 TOTAL。未观测值是 null，不是 0。
跨进程时钟无法对齐时仅保留 work_s 和原始相对本进程的时间，不伪造 wall_s/HANDOFF。
成功/失败是现有软件控制逻辑的结果，独立物理成功仍需实验者检查。
恢复事件记录原有抓取规划重试、二次观察重试、Hybrid 节点修复、任务重规划；
数量是这些层级的事件数，不等于整条任务从头重跑次数，也不包括 MoveIt 内部搜索次数。
规划器内部规划/候选失败仍在 MOTION_PLAN failed_calls 和原 ROS 日志中。

  cd '/home/wpy/projects/armcode-agent (1)/armcode-agent'
  bash scripts/run_fr3_timing_trial.sh pilot01 --execute_robot --verify_place_vdm

只有显式 --execute_robot 才运动。--verify_place_vdm 在这一实验命令中启用原有
放置验证技能，以便实际测 VERIFY；抓取即时验证仍维持原默认，未开启。
这个额外验证选项是实验协议的一部分，不改原校验阈值或失败处理。
预览保持原默认，关闭预览窗口的人工等待有独立 span，并包含在 TOTAL 中。
若以后统一改为 --no-visualize-selected-grasp，应建立新实验标签，勿混算。
此脚本默认 policy_backend=template，即原指令图+模板技能路径。
要测 Hybrid 节点代码生成，用同一命令追加 --policy_backend hybrid 并换实验标签；
不要把当前模板基线宣称为通用 CaP/PMIR 已接入真机。

首次通过后，将每次布局、容器位置、速度、相机模式和选项保持一致。

汇总（默认仅收 execute_robot=true 且 real 硬件配置的任务，仍包括真实任务早期失败）

  .venv-mobileclip2-fr3/bin/python -m runtime.experiment_timing runs \
    --experiment fr3_two_object_graspnet_v1 \
    --output runs/experiments/fr3_two_object_graspnet_v1

生成 baseline.json、trials.csv、summary.csv。
按目标、布局、硬件配置摘要、项目 Python 源码摘要和运行选项分条件组；每组再按 ok/failed/error/interrupted
以及是否观察到恢复事件分组。不同配置不混成一个平均值。run_id 去重。
mean/P50/P90 基于每轮阶段 wall_s；分位数采用线性插值，missing 不填 0。
failed/error 组的耗时可能是不完整任务的前缀，不能与完整成功组等价比较。
建议至少 10–20 轮正式任务后再讨论 P90；当前无真实样本，不给优化收益数值。
