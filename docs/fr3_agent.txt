夹爪闭合电流反馈（2026-10-13）
  Robotiq 返回 gCU 电机电流，驱动以 current_ma（原始值 * 10 mA）记录，同时记录
  实际位置、目标位置、gOBJ、故障和相对时间。电流不是指尖牛顿值，也不是力传感器读数。
  当前 YAML feedback_log_dir 已开启开合过程记录，目录为项目 runs/gripper_feedback。
  每次动作打印 JSON 日志路径；session_info.last_motion_feedback 保存摘要。
  close_current_limit_ma: null 表示只记录，尚未启用主机端电流阈值停止。
  标定后填写 10..2550 的整数（10 mA 的倍数）；不提供未经测量的默认停止阈值。
  达到阈值会发送 rGTO=0 并确认停止，抛出 GripperCurrentLimitError，中止抬升/运输。
  不自动张开、不自动重试、不把电流上升伪装成夹持成功；停止后的 gOBJ 不用于接触判断。
  未触发电流保护且闭合正常完成时，Agent 不再要求原生 closing contact 才抬升。该保护只作用于本驱动发出的闭合
  动作，不是搬运中的恒力控制，也不取代夹爪内部控制。默认前台状态采样约 50 ms，
  还受串口/调度延迟影响；不能保证检测到短暂峰值或避免软盒在检测前发生变形。
  开合指令覆盖 speed/force 不会关闭 YAML 中已设的电流停止阈值。

FR3 姿态筛选（2026-10-13）
  姿态为 fr3_link0 中标定转换后的 fr3_link8 RPY；当前 TCP 坐标轴与法兰平行。
  默认目标 rx=pi、ry=0，rx/ry 周期角偏差各不超过 65 度，不约束 rz。
  综合分 = 当前模型原始分 - lam_rx * rx偏差(弧度) - lam_ry * ry偏差(弧度)。
  默认 lam_rx=lam_ry=1。先应用姿态约束，再按综合分排序；当前关闭候选桌面间隙检查。
  默认 best_good：选择综合分最高者。随机模式也只从满足全部约束的候选中选。
  在原启动命令后追加：
    --grasp-selection-mode random_top_k_good --grasp-random-select-top-k 5
  加 --grasp-random-seed 42 可对同一候选池复现随机选择。
  可调 --grasp-target-rx / --grasp-target-ry（弧度），
       --grasp-max-rx-tilt-deg / --grasp-max-ry-tilt-deg（度），
       --grasp-lam-rx / --grasp-lam-ry（非负惩罚系数）。
  不旋转或修正候选，不在没有合格候选时退化成原始最高分；MoveIt 检查仍然执行。
  anygrasp/filtered_candidates.npy（GSNet 为 gsnet/）保存点云筛选后的完整池；pose_selection.json 保存逐候选
  角度偏差、综合分、姿态/桌面合格状态、随机池和最终选择。grasps.npy/json 和可视化
  始终只指向最终选中的一个抓取。此逻辑不会解决上游碰撞筛选已将候选清零的情况。

    enabled: true                     # false 则不复用 RGB-D 或观测 skill 结果
    position_radius_m: 0.02            # 法兰位置欧氏距离 2 cm
    orientation_radius_rad: 0.08726646259971647  # SO(3) 相对旋转角 5 度
    max_age_s: 30                      # 从原始图像采集时刻起算，命中不续期
    max_entries: 16                    # 图像与观测结果共享的有界 LRU 条目数
  缓存支持多个历史观测点；离开后返回，在有效期内仍可命中。Euler 角跨 +/-pi 不会误判。
  原始图像、深度、点云路径、采集时间、before/after 法兰位姿和手眼标定保持绑定。
  不把旧像素配上当前 FK；缓存只在进程内使用，不把历史任务 JSON 恢复为新的有效位姿缓存。
  检测/OCR 配置或后端实例变化后，不沿用此前的成功识别结果。

  失效与强制刷新：
    抓取、放置、清障执行开始/结束，以及失败或异常路径，使旧观测失效（全局保守失效）。
    识别失败、抓取规划重观察、Gate probe、主动视角清障检查、清障后复查、放置前后验证
    均重新取图；新任务也不沿用上一个任务的观测帧。
    手工移动物体后可调用 context.camera.invalidate_observations('external_scene_change')；
    特定操作需要始终新图时，使用：
      from runtime.observation_memory import fresh_camera
      with fresh_camera(context.camera, 'manual_probe'):
          result = robot.observe('目标名称')
    fresh_camera 作用域会绕过图片和观测结果两层缓存。
    日志 [observation_cache] wrist image hit 表示只跳过相机采集；
         [observation_cache] medicine(...) skill hit 表示识别也跳过。
    context.camera.observation_memory.stats 可查看 hits/misses/invalidations。
    原有容器基座坐标放置计划仍属于任务规划缓存；其存在不代表当前视角有新的可见性证据。

  静态桌面先使用小范围/短有效期；动态遮挡评估可设置 enabled: false 或强制刷新。

2026-10-21 并发一致性与候选感知流水线
  本节补充上一版位姿缓存的并发约束。当前执行器仍按动作依赖顺序运行；
  开放的是同一份保存 RGB 图像上的候选分割/OCR 流水线，不是多个抓取/放置同时执行。

  稳定失效机制：
    ObservationMemory 使用 RLock 保护缓存查找、版本变更和结果提交。
    epoch 表示观测代次，强制重拍也会推进；scene_epoch 表示场景版本，场景失效时推进。
    抓取、放置、清障的底层执行函数统一进入 scene_mutation：
      获取共享设备锁 -> 推进版本并标记执行中 -> 执行 -> finally 再失效并退出执行中。
    操作失败、异常、调用方绕过 SimpleRobotActions 直接调用这些底层执行函数，仍覆盖此路径。
    物理操作导致失效时，通过弱引用回调同步清理 robot.observations 与 robot.place_plans；
    保留任务进度和放置数量。仅强制重拍不会把清障正在使用的输入证据提前清掉。

    感知工作可以在后台继续，但只能返回局部结果。写入 Agent 状态之前必须原子检查：
      图像来源代次 == 当前 epoch，而且当前不在物理执行中。
    校验与写入位于同一个锁内；写回缓存和目标/容器记录也属于同一次提交。
    旧的成功结果返回 stale_observation，旧的失败结果也不能清空新代次观测。
    last_wrist_capture 改为线程局部变量，防止 A 任务误用 B 任务的图片位姿。
    采集过程中若发生外部显式失效，也会拒绝返回该帧。
    抓取计划携带来源观测代次，执行入口再次校验；容器基座放置计划校验 scene_epoch，
    允许在场景未变时拍摄放置前验证图，但不能跨物理场景变更继续使用旧计划。

    相机 RGB-D/FK 绑定与物理执行共用设备锁；FR3 旧位姿适配器也使用该锁。
    相机不会与这些 Agent 运动入口交叉采集。纯观察点移动不会主动使整个静态桌面失效。
    以上为当前进程内 Agent 路径的一致性保证，不能检测其他终端的 ROS 运动或人的物体移动。
    外部变化仍调用 invalidate_observations('external_scene_change')；重新启动任务会清除旧证据。

  已接入的并行：
    config/hardware/fr3.yaml -> perception.parallel_candidate_workers: 2（允许 1..4，1 为串行）。
    至少两个候选且 use_sam_for_selection=True 时，分割与 OCR 按候选交叠：
      GPU: SAM(A) -> SAM(B) -> ...
      CPU:           OCR(A) -> OCR(B) -> ...
    同一 GPU 资源一次允许一个 SAM3 / GroundingDINO / 参考图匹配 / FR3 抓取推理调用；
    同一 PaddleOCR 服务也串行访问。GPU 推理与 CPU OCR 可以同时进行。
    线程池有界，候选结果仍按输入顺序合并，保持原有目标排序语义。
    每帧分析和每个候选有独立 UUID 输出目录，避免 mask、crop、OCR 文件相互覆盖。
    worker 缓冲 UI 事件，由调用线程按顺序发布，不让后台线程直接调用 UI。
    每阶段检查来源代次，过期后停止后续候选阶段；已进入模型的调用需等其返回后丢弃。
    共享服务首次加载加锁，防止两个 OCR 请求各自初始化一份模型。
    单候选、bbox-only OCR、参考图快速识别分支保持现有顺序；没有为凑并发强制启动 SAM。

  后续优化顺序：
    1. 同一帧一次检测/特征提取，多目标查询共享候选；合并同键的在途请求。
    2. 把检测、OCR、深度/平面证据、遮挡图、抓取规划整理为有依赖和资源声明的任务图。
       状态提交与运动授权由一个执行器负责，工作线程只处理不可变输入并返回局部结果。
    3. 建立区域与对象依赖后，将全场景失效缩小到受影响区域；届时才值得在机械臂执行时
       预计算其他区域目标。当前全局失效会丢弃旧场景的预计算，不保证这种投机计算能提速。
    4. 记录实际采集、模型排队/推理、观察移动和执行耗时，再确定 workers 和批处理大小。
    5. 统一 observe 失败、重试预算、Gate probe 与重新规划的状态，避免重复做低收益观测。
