# 同一任务内容器固定（2026-10-22）

任务约定：执行期间目标容器的身份和基座坐标不变。Agent 在任务开始时成功定位容器后，后续抓取、清障、放置和腕部相机移动均复用该容器计划，不重新拍摄或识别容器。沿用原启动命令，无需新增参数；修改后的代码需要重启 agent 才会加载。

“一次定位”指一次成功的容器定位技能；首次定位仍可包含原有粗定位和近距离精定位两次采集。首次定位失败或没有生成完整、有限的 approach/place/lift 六维位姿时，不锁定缓存，沿用首次定位的失败处理。

## 缓存与执行

- `skill_lib/actions/task_containers.py` 保存进程内、本任务专属的容器基座放置计划，并绑定任务 ID。
- 抓取、放置和清障仍会清除旧 RGB-D、药盒观测、掩码和遮挡关系；容器的基座坐标计划独立保留。计划中原图、像素框等字段仅用于历史审计，不代表当前帧。
- 放置前沿用已完成的任务内容器定位事实，不再把蓝盘的颜色/语义分数当成需要再次 OCR 的依据。日志中的 `fixed_for_task=true` 表示此约定；相应 CSC=1 表示该离散前提已满足，不表示视觉识别概率为 100%。
- 保留夹持状态、容器可放置条件、原有放置计数与空间规则，以及原机械臂运动规划和故障处理。
- 放置执行边界验证任务 ID 和已登记的位姿，仅允许原有配置的放置槽位偏移。注册计划可以跨抓取/清障导致的 scene_epoch 变化使用；普通未注册计划继续执行原场景版本检查，药盒抓取的观测代次检查也保留。
- `new_task` 清除容器计划、任务绑定和放置计数；新机器人执行对象也有新的任务 ID。执行记忆 JSON 不能赋予旧计划在新任务中的信任。
- 显式调用 `_invalidate_container_cache(...)` 仍可清除指定容器及其别名记录，要求重新定位；普通抓取和清障不会调用此清除入口。
