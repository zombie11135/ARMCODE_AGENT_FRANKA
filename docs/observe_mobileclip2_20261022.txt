一、范围和实际调用链

  原任务接口不变：robot.observe(obj)。
  调用链：skill_lib/actions/observation.py::_observe_medicine_once
    -> FindAndGraspMedicineSkill.run(plan_grasp=False, execute=False)
    -> _recognize_image -> RecognizeObjectSkill -> ObjectReferenceService。

  原 OCR 路线会循环 DEFAULT_TARGET_PROMPTS 的五个元素：medicine_box 加四个描述，
  融合候选框、逐个候选提取 OCR、按任务关键词排序，再按配置验证选中目标的文字。
  项目已有可选图库快速分支，但原来只接第一代 MobileCLIP，且失败会自动回退 OCR。

  本次正式配置改为：
    同帧 RGB-D 采集 -> 单次 DINO 药盒检测 -> 候选图批量编码
    -> 每类最相似 3 张参考图的余弦相似度均值
    -> 查询目标必须排名第一、相似度 >= 0.80、领先其他类别 >= 0.02
    -> 返回选中实例和原格式 grasp_input。
  图库仍为每张参考图片一个 512 维向量，共四类、45 张，不做每类向量平均。
  模型/图库为进程内复用；候选特征按图像内容哈希和 bbox 缓存。
  同一张图查询多个已登记药名可复用检测和候选编码。
  换图、换检测参数、换检测后端会重新检测；这不是整项抓放任务只调用一次 DINO。

  默认 target_name=medicine_box，检测服务一次展开以下六段文字：
    rectangular medicine carton. pharmaceutical paper box.
    medicine package with printed text. drug package box.
    medicine bag. medicine package.
  DINO 阈值仍为 0.22 / 0.18；保留原几何过滤和技能 max_instances 默认 12。
  自定义 target_prompts 列表仍可传入，图库分支合并成一条提示进行一次检测。
  保持既有 RGB 短边缩放到 224、中心裁剪的预处理，没有借本次接入改变识别特征。

二、输入输出兼容处理

  observe(obj)、FindAndGraspMedicineSkill.run(...) 的原参数和 SkillResult 保持可用。
  成功结果保留 image_path、prompts、detections、instances、selected_instance、
  selection_result、ranked_candidates、ocr_verification、grasp_input。
  instances 包含全部候选，selection_result.selected_index 对应该列表中的原位置；
  修正了旧图库快速分支只返回一个 instance、却保留原候选索引的不一致。
  selected_instance 保留 bbox、object_id、confidence、image_path、mask/crop 字段。
  为选中目标保存裁剪图片，供调试和既有下游代码读取。
  grasp_input 沿用原构造函数：RGB、depth/depth_npy、相机内参、深度尺度、
  capture_geometry、时间戳和 observation_provenance 不由新识别器生成或更改。
  本次没有修改像素到三维、AnyGrasp、MoveIt、夹爪、放置和缓存失效规则。

  未执行 OCR 时保留兼容字段：ocr_text=""、ocr_texts=[]、ocr_success=False、
  ocr_avg_confidence=0；ocr_verification=None。绝不把药名/向量分数伪造为 OCR 结果。
  图库依据通过 identity_evidence 返回，标明 encoder_model、identity_id、score、
  class_margin、阈值、图库版本及图像哈希；分数不是概率。
  selection_result.score 在该分支表示图库相似度，match_type=reference_gallery。
  旧 OCR 参数 min_score、ocr_padding_px、merge_iou 等保留供旧路线使用；
  图库分支的接受门槛由 references.yaml 指定。
  原有 verify_ocr=True 不强制对已通过图库验证的目标再次 OCR；显式 strict 模式除外。

  Gate 继续读取独立身份依据，并检查深度和遮挡，不以图库通过代替抓取可行性判断。
  修正共享简称经场景消歧后证据 query 变成内部 ID 的情况：证据保留调用者 query，
  并另存 resolved_query 和稳定 identity_id，保持 Gate 与原任务目标对得上。
  场景消歧与最终匹配使用相同检测参数，避免因此追加一次检测。

三、失败和旧流程兼容

  本地配置 recognition_policy=reference_only：未登记、低相似度、类别分差不足、
  空检测或模型错误都明确返回失败，不自动再跑五次 DINO 和 OCR。
  保留原扫描/重新观察机制，由上层决定换视角或结束任务。
  注册新药品/别名请继续使用 hardware.reference_cli；图库中未登记的名称不会被猜测匹配。

  显式兼容入口：
    recognition_policy: reference_then_ocr  恢复“图库优先，失败回退 OCR”；
    enabled: false                         停用图库，走原路线；
    skip_reference_matching=True           单次强制旧路线；
    ocr_verify_strict_mode=True              保留原严格 OCR 语义。
  旧 YAML 未声明新字段时保留第一代编码器及自动 OCR 回退语义；新模板显式选用第二代。
  第一代权重/向量库未删除，但正式本地配置不再加载第一代模型。
  原 inspect_medicine_candidates 近距离逐候选 OCR 实验技能仍保留；它不是
  robot.observe(obj) 的任务入口，本次不改其近距离移动和全场景 OCR 实验行为。
  grasp() 使用同一个 _recognize_image，因此它内部的身份识别同步采用新路线；
  观测与抓取之间原有图像/位姿缓存有效性检查仍然生效。

四、修改文件

  services/reference_encoder.py（新增）
    懒加载 MobileCLIP2-B、本地 checkpoint、与已验证图库一致的预处理及批量编码。
  services/object_reference_service.py
    新模型/策略配置；模型专属缓存键；加载已有第二代向量库；记录编码器身份。
    载入预建库检查模型、权重哈希、预处理、向量文件哈希、归一化和逐行身份。
    按稳定身份编号和图片哈希重排，避免 gallery.json 与建库时顺序不同造成类别错配。
    新增参考图导致预建库不全时重建本地特征缓存；不兼容/损坏库返回错误。
  services/detection_prompts.py（新增）、services/grounding_dino_detector_service.py
    共享原六段药盒描述；新增列表合并，不改变原检测模型和描述内容。
  skill_lib/perception/reference_recognition.py
    一次检测调度、完整候选接口、独立身份证据、失败证据和调用日志。
  skill_lib/combound/find_and_grasp_medicine.py、services/object_names.py
    按策略决定回退，统一消歧参数，保留调用者身份和旧入口。
  config/perception/references.example.yaml、requirements-reference-recognition.txt
    正式模型和策略模板；修正旧模板 top_k_refs/log_path 与实际配置字段不匹配的问题。
  tests/test_observe_gallery.py（新增）、scripts/check_core.py
    17 项新回归；将图库相关 CPU 测试加入项目规定的离线验收入口。
  skill_lab/test_observe_gallery_offline.py（新增）
    使用正式识别函数、真实模型和保存照片的离线回放，断言每帧一次检测/批量编码。
  docs/reference_recognition.txt、THIRD_PARTY.md
    标明旧说明是历史记录，并指向本次迁移说明。
  本机 config/perception/references.yaml 同步更新；本机配置、模型和向量缓存不提交。
  最新共享分支已纳入图库清单和参考照片，本次功能提交不改动这些共享数据。

五、本机配置及复现

  权重与特征库的 Release 附件、下载校验及解压说明：docs/observe_assets.md。
  正式权重：models/mobileclip2-b/mobileclip2_b.pt
  权重 SHA256：144b1344f5f01f08af8be1077f0db5eec95bf0fd1e349c1e9ca6102724448486
  预建库：data/object_gallery/vector_libraries/mobileclip2_b/index.npz
  编码器：encoder_model: mobileclip2_b；策略：recognition_policy: reference_only。
  Agent 的硬件 profile 必须通过 perception.reference_config 指向该配置，重启进程生效。

  已在本机 .venv-mobileclip2 中补齐 DINO/技能离线所需依赖，pip check 通过。
  验证栈：Python 3.10、torch 2.9.1、torchvision 0.24.1、open_clip_torch 3.3.0、
  timm 1.0.30、transformers 5.5.4、numpy 1.26.4、scipy 1.15.3。
  实机 Agent 解释器也必须具备这些兼容的识别依赖；仅修改权重路径不足以切换模型。
  本环境是离线识别环境，没有替实验室机器人配置 ROS、相机、夹爪或标定。

  在项目根目录执行：
    .venv-dev/bin/python scripts/check_core.py
    .venv-dev/bin/python -m pytest -q tests/test_observation_memory.py tests/test_perception_pipeline.py tests/test_reference_capture.py

  真实照片回放（只读图，不启动任何硬件；需要 GPU）：
    .venv-mobileclip2/bin/python -B skill_lab/test_observe_gallery_offline.py \
      --images data/object_gallery/test_image \
      --output runs/observe_mobileclip2_replay_new

  可追加 --visual-reference runs/dino_gallery_test_20261022/run_20261022_161336/visual_reference.json
  核对本轮五张照片的人工参考框。换照片后需相应更换标签，不要沿用旧标签评新图。
  每次识别明细：runs/reference_recognition/<id>/recognition.json。
