3. 研究共识与实际实现必须区分

设计方向：
- 依赖分析器：CaP Python -> PMIR -> 动态依赖图 G_t=(V_t,E_t)。
- PEIP + Memory：未来的分支预测、推测计算、结果缓存及有效性管理。
- Recovery-Aware Runtime：资源调度、状态验证、提交及局部恢复。
- 依赖分 data/control/physical；资源冲突是独立调度约束，不自动等同于因果依赖。
- 用 R(u)、W(u) 描述读写状态；已确认且状态仍有效的事件可提前释放后续计算。
- 只推测计算，不因预测而提前执行不可逆物理动作。
- 优化实际任务完成时间，成功率、资源和安全作为约束；失败代价、验证和收尾也要计时。

当前只实现最小可运行子集，尚未实现：
  通用 PEIP 分支预测、PMIR CODE_GEN、新技能源码自动理解、通用物理影响范围推断、
  通用缓存管理、最小失效子图自动恢复、抽屉或真实倒水技能。
已有生产 Hybrid 的下一节点代码预生成，不等于上述 PMIR 框架已经实现通用分支预测。
当前 Naive 的一次重采只是实验对照行为，不等于已完成局部错误恢复框架。
不要将设计共识写成已经通过实验验证的完整 Runtime 能力。

  不支持任意 Python、属性/导入/递归、动态 range、分支内部提前 return；不调用 eval/exec。

  可登记黑盒技能形成保守屏障；没有仿真 handler 时入口会拒绝实际运行。
runtime/pmir/scheduler.py
  单 CPU worker，主线程推进物理 generator；有 serial / naive / dynamic 三种模式。
  保留依赖、资源、版本校验；未实现多个机械臂同时运动。
  ForegroundCosts 在此文件内记录互斥前台区间，不是独立新架构模块。
  失败/陈旧证据停止本轮、保留完成前缀并收尾后台；不物理回滚、不自动从头重做。
simulation/pmir/adapter.py
  复用既有 RobosuiteBackend。只有主线程调用 MuJoCo/EGL；worker 只得到只读图像快照。
  物理操作真实通过控制器步进/接触完成，不通过写 qpos 冒充抓放。
  相机、仿真状态监测和可见性事件均在 owner 线程；snapshot/probe/step 中已有细分计时。
simulation/pmir/perception.py
  已知颜色/尺寸/桌面高度的 RGB-D 方块几何估计，后台无物体/机器人真值输入。
  可选每次 PERCEIVE 的 sleep 延迟；实际等待区间与处理时间分别记录。
simulation/pmir/experiment.py
  实验入口、源码归档、运行顺序、结果与配对统计、成本/关键等待计算。
scripts/plot_pmir.py
  从保存的数据生成依赖图、时间线、延迟曲线、成本堆积图和无效计算图；不会再执行任务。
simulation/robosuite_backend/
  用户已安装并提供的 Panda/MuJoCo 接触物理后端；最近计时扫描没有修改它。

默认程序：
  def policy():
      pick_place("red_cube", "red_goal")
      pick_place("blue_cube", "blue_goal")
展开 28 个节点。每次抓放：CAPTURE、PERCEIVE、GRASP_PLAN、MOTION_PLAN，然后
raise / approach / descend / close / lift / transport / lower / release / retreat / settle。
close/release 为 GRIPPER，settle 为 VERIFY，其余物理阶段为 MOVE。
GRASP_PLAN 是解析的固定竖直抓取；MOTION_PLAN 是名义笛卡尔路点，不是 AnyGrasp/MoveIt。

明确依赖仿真真值的部分：物体速度/版本监视、双指接触、抬升检查、持物偏移、最终放置。
目标位移超过 1.5 mm 或转动超过 0.04 rad 时递增版本；阈值不是已证明通用安全的物理模型。
初始及 lift/release/settle 后采集图像并做可见性/稳定检查；掩膜 >=25 像素且稳定才放行。
不能在 A 移开前为完全不可见的 B 编造抓取位姿。

模式定义（必须保留公平口径）：
  Serial：按节点顺序运行，同样承担状态监测和成功判据。
  Naive：首次隐式 CAPTURE 不等待可见性门控；若生成空观测，丢弃结果，确认可见/稳定后
         最多重采一次。物理顺序、版本检查仍保持；显式 observe 的 false 分支语义不改变。
  Dynamic：首次隐式 CAPTURE 就等待已确认的可见/稳定事件，避免上述无效早算。
Naive 是本实验明确规定的比较策略，不能泛称所有传统流水线。

6. 最新实验：已完成，无需为了“建立基线”从零再做

根目录：runs/experiments/pmir_cost_sweep_20261110/
正式数据在其 sweep/ 下。
两场景 independent / occluded × 5 延迟 × 3 模式 × 6 次重复 = 180 正式回合。
另有 6 次最大延迟预热，排除于正式统计。固定 seed 7；每个条件块三种方法相邻执行，
六轮使用三种方法的全部六种排列，每个方法在各运行位置出现两次，各轮打乱条件块顺序。
计算延迟为每次 PERCEIVE 额外 0/50/100/200/500 ms；0 ms 仍执行真实几何处理。
Serial/Dynamic 一轮各两次有效感知；遮挡 Naive 通常三次（含失败早算），每次都承担延迟。
这是返回延迟控制，不模拟 CPU/GPU 饱和、GIL/显存争用或真实模型计算成本。

180/180 完成，120/120 个 Serial 与候选的配对满足初态、动作顺序、成功和步数条件。
每场景内所有模式/负载/重复的初始 qpos 和 RGB 哈希一致。
independent 固定 773 控制步、38.65 s 仿真控制时间；occluded 固定 775 步、38.75 s。
注意跨场景布局并不相同：独立布局为 seed 7 的轻微扰动，遮挡布局为固定对齐，相机也不同。
因此不能将跨场景收益差异完全归因于遮挡；不是严格的只改变遮挡程度的因果实验。

结论：
- 原生计算只有几 ms，流水线没有稳定优势；本次 Naive 在 0 ms 下两场景均 6/6 次慢于 Serial。
- 无遮挡组最小明确获益的已测试点是额外 50 ms；遮挡组是 100 ms，均为 6/6 配对更快。
- 遮挡 50 ms 的 Dynamic 净节省中位数 10.4 ms，探索性 95% bootstrap 区间 -19.2～68.1 ms，
  跨零。不能把 50/100 ms 写成普适或精确的盈亏平衡阈值。
- 遮挡 Naive 的 30 个正式回合每回合一次无效早算，共 30 次；Dynamic 为零。
- 遮挡所有负载下，Dynamic 相对 Naive 的配对区间均跨零，尚未证明其稳定更快。
- 这些失效是遮挡空观测，不等于已验证通用状态/缓存失效处理。
中位数表直接相减不等于“配对差值的中位数”；效应请读取 comparison.json 的 effects。

7. 耗时口径：后续 agent 最容易误读的部分

wall_duration_s 是 Scheduler 开始记录到后台收尾结束，覆盖任务内采图、监测、验证、
调度、事件日志和等待。编译/环境初始化/运行前后图像导出不在该窗口，不能叫冷启动总耗时。
task_timing_wall_s 还包含调度器构造、最终目标检查与计时包装，本批中位额外约 2.8 ms。
fast 模式等纯计算时冻结物理；real_time 模式尽力按 20 Hz 节拍并在等待时维持控制。
仿真控制时间、主机墙钟和真实 FR3 完成时间不同；本批使用 fast，未测真实 FR3。

旧日志 MOVE span 是整个微操作的驻留区间，可能包含穿插采图/调度，不能全算机械运动。
旧 CAPTURE 节点也没覆盖所有监测采图。旧数据未分测的类别在 historical_decomposition.json
中保持 null，不能把未分类残差全部归给调度。不要用新测量回填为旧数据的“实测分项”。

当前 cost_profile.json 的主线程区间互斥、连续，加和严格等于 wall_duration_s。
后台感知是重叠的另一条轴，不能再与前台简单相加。主要字段：
  image_acquire_format：渲染、RGB-D 格式转换及后端内部复制，扣除独立验证/日志。
  image_snapshot_copy：额外制作不可变快照的复制，不代表后端所有内存复制。
  state_validation：可见性掩膜、速度/版本、接触和放置检查；掩膜计算归此类，避免重复记账。
  scheduler_decision：依赖/资源/就绪/分支扫描、分派和事件边维护。
  physics_step：实际 env.step 的控制器计算和物理积分，不是真实机械臂纯运动时间。
  robot_control：微操作推进、插值及控制外围工作。
  compute_wait_poll：无物理操作推进时的计算等待，可能含计算结束后的轮询尾部。
  profiling_analysis：分析等待原因的仪表成本；其他计时成本也分布于各类/维护项，非零开销。
  logging / runtime_bookkeeping / foreground_plan / shutdown_wait：其余前台工作。
  perception_wall_s：PERCEIVE 总墙钟；另报 injected_wait_wall_s、去注入时间和 worker_thread_cpu_s。

exposed_critical_compute_s 的严格定义：没有物理微操作推进，worker 确实在执行，且该
worker 位于下一物理节点未完成的数据链，或占用了该链需要的资源。保存 node/attempt/
blocked_physical 与 data_dependency/resource_conflict，可回看等待原因。
这是关键等待链上暴露计算时间的可核查下界，不是整张反事实执行图的最长路径，也不包含
计算间接拖慢物理仿真的干扰；不要把这个限制删掉。

三个不同量：
  compute_physical_residency_overlap_wall_s：与物理微操作整个驻留区间交集。
  compute_actual_physics_overlap_s：与独占 env.step 区间交集，排除穿插的采图等。
  saved_wall_s：同条件成功配对的 T_serial - T_candidate，才是实际净节省，允许为负。
旧 compute_physics_step_overlap_wall_s 是较宽的 backend._step 区间，还含后端检查；
不要与新 env.step 独占口径混用。

原生 0 ms 注入、遮挡 Dynamic 的主要前台成本均值：采图/复制约 188 ms、验证 143 ms、
调度 37 ms（Serial 约 7.5 ms）、物理仿真/控制约 2288 ms；两次感知墙钟中位数仅 6.37 ms。
下一步应先解释和减少可测的重复工作，不能只盯几 ms 的感知计算。
