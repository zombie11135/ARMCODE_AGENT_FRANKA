文本和图片先各热身一次，以下是热请求完整调用耗时；不包含服务冷启动。

视觉限制：9B 的遮挡布尔字段命中 1/4，8B 为 3/4，但这不是视觉准确率。

所以不把 JSON 合法或单个布尔值命中当作完整视觉判断正确，几何证据仍是遮挡主依据。
线上服务在热身时连接被拒绝，没有获得当前线上耗时，不能计算线上到本地的加速比。

二、与感知/抓取模型共存

8B 原预算 0.45 + DINO/MobileCLIP2/两份 SAM3 时，AnyGrasp 出现 CUDA OOM。
预算降至 0.38 并释放空闲分配器缓存后可通过，峰值 23751 MiB，余量仍小。
随后 bbox 分割和在线遮挡提议共享同一份 SAM3 权重，保留独立处理器/帧状态。
最终同时驻留本地 VLM、DINO、MobileCLIP2、SAM3，顺序调用 SAM3、AnyGrasp 和 VLM 全部通过。
最终整卡采样峰值 20135 MiB（19.66 GiB），约留 4 GiB 余量。
AnyGrasp 使用历史约 902494 点的完整场景请求；RGB 模型使用另一份保存图像。
这是资源共存测试，不是同一帧几何一致性或闭环任务完成测试。
显存为整卡 nvidia-smi 每 250ms 采样，包含系统占用，可能漏掉极短峰值。
共享前后 bbox 掩码逐像素一致=True；
提议数量 6/6，掩码一致=True，最大分数差=0.0。
一致性检查仅覆盖这张保存图像，结构共享的兼容边界另有离线回归。

三、实际框架接入

local VLM 选项统一覆盖规划、恢复、fallback、VDM 和遮挡校验的地址。
本地服务仅监听回环；运行时设置 HF_HUB_OFFLINE、TRANSFORMERS_OFFLINE 并关闭用量统计。
本地规划只输出 op/target，程序构造原有 PlanGraph；恢复只输出菜单索引和简短理由，
宿主绑定本次冻结快照的完整 ID，沿用原动作合法性/观测版本校验。
GPU 重推理串行协调，保留运动和 CPU 处理与推理重叠的流水线。
AnyGrasp/本地 VLM 调用前释放空闲缓存，不卸载活跃权重或改变抓取参数。
真实 app 入口以 --no_run_executor 验证了双目标规划→代码生成：
grasp(西瓜霜)→place(blue tray)→grasp(抗病毒口服液)→place(pink tray)。
planner 元数据为 llm / compact_actions_v1，图库绑定正确，没有使用启发式回退。
